# Capability areas

The left column is what in a task calls for the area; the right column says what a matching skill should cover. Concrete skill names come from the current environment (see SKILL.md), so this table deliberately has none.

| Area (task trigger) | A matching skill covers |
|---|---|
| creative task, approach unclear | structured ideation before design |
| code standards for the project's language / framework | conventions enforcement |
| framework routing, rendering, data fetching | framework patterns and anti-patterns |
| UI component state and effects | component and effect discipline |
| performance: rerenders, bundle, virtualization | performance guidance |
| forms and validation | form + schema validation patterns |
| URL as state: filters, tabs, dialog stacks | URL-state management |
| styling, classes, theming | styling system conventions |
| the project's UI component library | component kit patterns |
| where code lives, layers, import boundaries | architectural layering |
| complex types, schemas, generics | type-level engineering |
| user input, API endpoints, secrets | security review |
| visual design of new UI | aesthetics, palette, layout |
| design system, tokens | token / theme consistency |
| accessibility / usability audit | a11y checks |
| final check before handover | verification discipline |
| manual UI check in a browser | browser-based testing |
